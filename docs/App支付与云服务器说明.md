# App 支付与云服务器说明

## 先说结论

小程序版现在可以直接走微信云开发。

但 **App 版不能直接复用 `wx.cloud` 作为前端调用方式**，因为：

- App 不是微信运行时
- App 不能直接调用小程序专属的云函数 SDK
- App 支付需要服务端生成正式订单与支付签名

所以，如果你要把 App 版做成真实可上线产品，**必须补一套独立的云服务器 / API 网关**。

## App 版至少需要的服务端能力

### 1. 业务 API 网关

建议你有一个公开 HTTPS 域名，例如：

`https://api.synaptic.com`

App 统一调这个地址，而不是直接调小程序云函数。

建议最少提供这些接口：

- 用户登录 / 设备登录
- 用户资料与认证资料
- 学校 / 学院列表
- 仪器列表 / 详情 / 发布 / 编辑
- 收藏 / 购物车
- 下单 / 订单列表 / 订单详情
- 聊天会话 / 发消息 / 客服介入
- 社区帖子 / 项目协作 / AI 任务

### 2. 支付服务

真实 App 支付至少需要服务端做这些事情：

- 创建业务订单
- 校验金额
- 生成微信 App 支付或支付宝 App 支付参数
- 接收支付回调
- 更新订单状态
- 做重复支付和伪造回调校验

也就是说：

**支付绝不能只在前端做。**

### 3. 文件服务

这些内容通常需要对象存储：

- 认证证明
- 仪器图片
- 协议附件
- 纠纷凭证

### 4. 异步通知服务

建议后面补：

- 订单状态通知
- 支付成功通知
- 认证审核通知
- 客服介入通知

## 建议的部署架构

最稳妥的创业版架构：

- App / 小程序前端
- `NestJS` 或 `Express` API 服务
- `MySQL` / `PostgreSQL`
- `Redis`
- 对象存储
- 支付回调服务

## 你现在这套代码怎么接

### 小程序

小程序目前继续用云函数没有问题。

### App

App 需要把：

`app/common/env.js`

里的：

- `useMock: true`

改成：

- `useMock: false`

然后把：

- `apiBaseUrl`

换成你真实的 API 地址。

## 支付现在能做到什么程度

当前 App 工程已经做了支付桥：

- 页面链路完整
- 支付按钮完整
- 支持演示模式模拟支付成功
- 真实支付预留 `uni.requestPayment`

但要变成 **真正可收款**，还差这 4 件事：

1. 真实服务端订单系统
2. 真实支付参数签发
3. 支付结果回调处理
4. Android / iOS 正式打包与签名

## 当前最现实的下一步

如果你要创业落地，我建议你接下来按这个顺序走：

1. 先把独立后端 API 搭起来
2. 再把 App 改成调用真实 API
3. 再接微信 App 支付 / 支付宝 App 支付
4. 最后做正式打包、签名和上架准备
