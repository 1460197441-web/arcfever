# 神经突触项目 Subagent 分工与执行方案

## 1. 总体原则

- 拆分维度按 `业务域 + 交付物 + 串联角色`，不按纯技术栈硬拆。
- 所有子代理先输出设计、边界和风险，再进入实现或审校。
- 总控代理统一维护 `状态机 / API 契约 / 联调节奏 / 验收口径`。
- 同一轮内避免两个子代理修改同一组文件，防止互相覆盖。

- 微信小程序前端：`pages/*`、`custom-tab-bar/*`、`utils/*`

## 3. Agent 编组

### 3.1 总控 Agent

- 负责人：主代理
- 职责：
  - 维护需求清单、优先级和联调顺序
  - 决定数据模型、API 契约、状态机
  - 汇总各子代理产出并做最终验收
  - 控制哪些问题立即修，哪些进入后续版本
- 直接产物：
  - 本文档
  - 计划与验收清单
  - 最终整合后的代码与发布包

### 3.2 产品需求 / 契约 Agent

- 当前分配：`Mendel`
- 职责：
  - 抽取当前项目的真实 MVP
  - 明确用户角色、核心流程、状态机和异常场景
  - 梳理 API 分组、字段定义和未决事项
- 只处理：
  - `docs/*`
  - 契约审阅，不直接改业务代码
- 交付物：
  - PRD/MVP 清单
  - 仪器/订单/支付/认证/纠纷状态机
  - API 契约总表

### 3.3 小程序前端 Agent

- 当前分配：主代理整合，必要时再派专门子代理
- 职责：
  - 保持所有核心页面符合首页风格
  - 修复小程序交易链路的前端入口问题
  - 处理 loading / empty / error 三态
- 负责文件范围：
  - `pages/*`
  - `custom-tab-bar/*`
  - `app.wxss`
  - `app.json`
- 严禁直接改：
  - `cloudfunctions/*`
  - `app/*`

### 3.4 后端领域 Agent

- 当前分配：`Aquinas`
- 职责：
  - 负责云函数里的真实业务规则、权限、状态流转
  - 审核真实支付、订单、客服、纠纷、认证链路
  - 补齐需要后端单独 owner 的规则
- 负责文件范围：
  - `cloudfunctions/gateway/*`
  - `cloudfunctions/bootstrap/*`
  - `utils/api.js`
- 关注重点：
  - 鉴权
  - 订单归属
  - 管理员权限
  - 支付回调与幂等

### 3.5 库存与规则 Agent

- 当前分配：`Erdos`
- 职责：
  - 审核库存模型、租期、订单可见性、卖家/买家两端流转
  - 找出并发、超卖、角色链路缺口
  - 约束哪些状态转换允许发生
- 负责文件范围：
  - `cloudfunctions/gateway/cloud-db.js`
  - 与订单/聊天/库存相关的 `pages/*`
- 当前重点：
  - 卖家能否看到订单和会话
  - 协议是否携带仪器上下文
  - 远程实验订单的空数据表现

- 只处理：
  - 审阅与清单，不直接改业务代码
- 重点范围：
  - 微信云开发环境
  - App 构建环境
  - 支付签约
  - 初始化脚本
  - 回滚与日志追踪

## 4. 推荐执行顺序

### 阶段 1：契约收口

1. 产品需求 / 契约 Agent 输出 MVP、状态机和 API 契约表
2. 后端领域 Agent 与库存规则 Agent 按契约确认规则边界
3. 总控 Agent 冻结这一轮允许修改的接口与状态字段

### 阶段 2：核心修复

1. 小程序前端 Agent 修复协议、订单、卖家入口和页面统一性
2. App 前端 / 体验 Agent 修复 mock、分类、认证、空态和导航
3. 后端领域 Agent 修复鉴权、订单归属和支付伪成功风险

### 阶段 3：支付与质量

1. 支付链路按“演示模式 / 真支付模式”明确分层
2. QA / DevOps Agent 输出冒烟清单与上线阻塞项
3. 总控 Agent 统一打包、复测并产出风险说明

## 6. 当前优先级最高的问题

### P0

- App 默认仍处于 `mock + 已认证种子用户` 模式
- App 支付是模拟成功，不是真实支付
- 小程序真实支付仍缺真实回调、签名和幂等闭环
- 后端仍存在“买家链路强、卖家链路弱”的结构问题

### P1

- 协议页部分入口没有携带 `instrumentId`
- 同一仪器无法按不同 `tradeMode` 同时入车
- App 认证页 picker 回填不一致
- 远程实验订单在订单列表可能出现空标题

### P2

- 管理页、订单页和部分内容页视觉风格未完全与首页统一
- App 底部导航尚未完成“线稿/实心”双态图标体系

## 7. 当前这一轮的验收标准

- 小程序与 App 的默认用户态一致，不再自动伪造认证身份
- 小程序与 App 的核心交易入口不再出现空参、空态崩溃或错误跳转
- 协议、订单、购物车、聊天至少买家/卖家双边链路可验证
- 所有关键页面具备 `loading / empty / error` 基本兜底
- 输出一份可执行的测试矩阵和上线阻塞说明
