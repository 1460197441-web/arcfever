# 神经突触最低额度 Subagent 配置

## 推荐编制

- 主控：主代理自己承担
- 产品 / 架构 Agent：1 个
- 前端 Agent：1 个
- 后端 Agent：1 个

总计：`3 个 subagent + 1 个主控`

## 为什么这样最省

- 少一次“同一需求重复理解”
- 少一次“接口契约反复改写”
- 少一次“文档 agent 讲一遍、实现 agent 再复述一遍”
- UI、库存、支付、测试这些高耦合主题直接并入主域，不单开常驻代理

## 角色边界

### 1. 主控

只做三件事：

- 维护任务清单
- 冻结接口契约
- 决定下一步由谁推进

### 2. 产品 / 架构 Agent

合并产品、UI、数据设计，统一输出：

- PRD 摘要
- 页面清单
- 状态机
- 表结构草案
- API 草案

### 3. 前端 Agent

只负责：

- 小程序 / App 页面与组件
- 请求封装
- 登录态与表单校验
- 联调后的页面收口

### 4. 后端 Agent

合并后端、库存、支付、测试主链路，统一负责：

- 数据库与接口
- 订单、库存、支付核心逻辑
- 权限与状态流转
- 管理端接口
- 联调后的风控与回归检查

## 最省额度工作流

1. 主控先让产品 / 架构 Agent 一次性产出：
   - PRD
   - 页面树
   - 表结构
   - API 草案
   - 状态机
2. 主控把这份产出冻结成唯一上下文。
3. 前端和后端只吃这份冻结上下文，不各自重新发散。
4. 联调时只补“变更单”，不重讲全项目。

## 什么时候才值得单开更多 Agent

只有满足以下任一条件，才额外开 subagent：

- 这个模块会连续产出很多内容
- 它和别的模块上下文差异很大
- 它需要长时间独立推演

否则不要拆。

## 当前项目建议保留的 3 个 Agent

- 产品 / 架构：负责“科研仪器租赁”的角色、状态机、页面树、数据模型、API 契约
- 前端：负责微信小程序 + App 端页面、视觉统一、请求接入与联调
- 后端：负责云函数 / 独立后端演进、订单库存规则、支付路径、管理接口

## 超短提示词

### 产品 / 架构 Agent

你负责把“神经突触”当前版本冻结成唯一产品契约。输出 PRD 摘要、页面清单、状态机、表结构草案、API 草案，并指出当前代码与契约不一致的地方。不要重复解释通用方法论，只围绕当前仓库。

### 前端 Agent

你只负责前端实现。严格按已冻结的页面清单和 API 契约推进小程序 / App 页面、组件、请求封装和联调修复。不要重新定义接口，不要扩展产品范围。

### 后端 Agent

你只负责后端实现。严格按已冻结的表结构、状态机和 API 契约推进数据库、接口、订单库存支付逻辑和管理接口。不要改动前端交互定义；所有状态变化都必须可追踪。

## 主控提醒

- 不要让多个 agent 同时重新解释项目背景
- 不要让前端和后端各自发明一套状态机
- 不要把支付、库存、测试拆成常驻代理
- 每轮只让 agent 输出“本轮新增信息”，不是全文复述
