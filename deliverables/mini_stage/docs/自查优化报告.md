# 神经突触小程序自查优化报告

## 第 1 轮：交易模型自查
- 将交易从单一租赁改为 `租赁 / 出售 / 租售皆可` 三种表现方式。
- 让押金、保险、平台服务费真正参与金额计算，不再只是展示字段。
- 修复月底日期生成溢出问题，避免出现 `2026-03-32` 这类无效日期。
- 将订单时间改为本地时间格式，避免 UTC 时间导致运营记录错位。

## 第 2 轮：下单闭环自查
- 重做仪器详情页，补齐交易模式、租期、保险、协议入口、违约规则、损坏责任。
- 重做购物车，改成按仪器逐单结算，避免多个设备混单后条款混乱。
- 重做订单确认页，强制要求确认协议和损坏责任说明后才能下单。
- 重做支付页与订单详情页，展示完整金额拆分、交付方式和争议入口。

## 第 3 轮：运营后台自查
- 补齐管理后台入口，新增认证审核、举报处理、纠纷工单 3 个后台页面。
- 学校 / 学院维护改成支持合并已有院校，避免重复添加。
- 纠纷发起后会联动更新订单状态，结案后同步回写订单状态。
- 举报与认证审核状态会真实反映到后台统计中。

## 第 4 轮：供给侧自查
- 重做发布页与编辑页，增加买断价、押金、精度参数、适用学科、服务包、违约规则、损坏责任。
- 发布逻辑增加已认证校验，未认证用户不能直接发布和下单。
- 新发布仪器补齐学校、学院、交易模式、保险、协议等字段，避免前后端口径不一致。

## 第 5 轮：一致性自查
- 将 `utils/mock.js` 与 `cloudfunctions/gateway/mock-data.js` 完全同步。
- 将原先“页面手工挂载”的底部导航，升级为微信小程序全局 `custom-tab-bar`。
- 完成所有 `app.json` 注册页面的文件补齐。
- 通过 JS 语法检查、JSON 解析检查、页面存在性检查。
- 用脚本模拟了租赁下单、买断下单、支付、聊天、客服介入、发起纠纷、后台读取统计等链路。

## 我直接修掉的现实交易疑点
- 用户未显式同意协议和责任说明就能下单：已禁止。
- 购物车多仪器一次性混合结算：已改成逐单结算。
- 出售模式沿用租赁逻辑：已拆开处理，出售不再要求租期和押金。
- 日期排期可能生成非法日期：已修复。
- 管理后台只有统计没有处置入口：已补齐审核和处置页面。
- 认证信息只是展示，不影响权限：已改为影响发布和下单权限。

## 仍建议尽快决策的创业级问题
- 是否接入真实支付托管与押金冻结。
- 是否接入真实文件上传与机构证明审核。
- 是否支持企业商家 / 学校实验室多主体入驻。
- 是否引入运费、物流模板、验货节点和签收凭证。
- 是否引入法务审核过的正式协议文本与电子签约。
